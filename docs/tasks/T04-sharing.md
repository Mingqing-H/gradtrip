## 4. 必须交付

### 4.1 传递协议与白名单

- snapshot / invitation / response / backup 四类统一 envelope，schemaVersion=1、payloadId、createdAt、body。
- snapshot 仅公开计划内容，不含成员私密资料、备注和实际账目；只读查看，不写原旅行。
- invitation 只含目标成员填写上下文，目标手工交通信息按规则显式确认后附带，不泄露其他成员映射。
- response 回传该成员资料和意向，原邀请/旅行/成员/约束版本与方案版本一致才可应用。
- backup 为单旅行完整备份，不含图片二进制、缓存和密钥；同 ID 默认另存副本，覆盖需预览与恢复副本。
- UTF-8→Base64URL→Hash 链接；长度 >8000 字节导出文件，不截断；文件上限 1 MiB。
- 损坏编码、未知 schema、跨源/错误 base、非法引用、超限和不支持模板版本均可解释地处理。

### 4.2 三个独立页面

- SnapshotPage：名称/日期/估算/按天日程/生成时状态，标记只读与不会自动更新，可另存为新旅行。
- JoinPage：目标成员与个人资料→方案意向两步表单，未知交通不显示假总额，生成反馈不称已提交。
- ResponsePage：摘要、复制反馈链接、下载文件；本地有原旅行时提供“预览并导入”，不自动应用。
- 从外部直接打开任何页面都能工作，不要求组织者工作台曾打开；不要假定前一步草稿存在。
- 接收端无法实时知道邀请是否过期，不宣称实时有效；组织者应用时才校验当前版本。

### 4.3 分享/导入/恢复面板

- 目标成员邀请、计划分享、完整备份明确区分，展示准确范围；过长链接和剪贴板失败可降级。
- 统一导入识别四类载荷并进入正确预览；反馈旧值→新值、有效性与过期原因清楚可见。
- 预览不写数据，点击应用时重新在事务内验证版本；重复 payloadId 不再次生效，重新提交需按规则预览替换。
- 成员反馈改变约束时一次性更新资料、失效旧意向、记录新意向和 responseId；禁止半份导入。
- 备份另存正确重映射所有实体 ID、清除原共识/邀请登记；覆盖前由仓库原子保留旧版恢复内容。
- 日程超出选择方案日期时阻止生成快照，并提供定位入口；草稿快照明确未确认。
- 本地恢复管理通过服务列出/预览/导出/删除恢复副本；损坏数据保留原始内容，不静默重置。
