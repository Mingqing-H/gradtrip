## 业务与存储证据

- 统一示例：6 位虚构成员、7 个候选（6 个目的地）、日程与 3 笔共 490 元的费用，无有效结算预锁；日期相对首次访问自然日生成。非示例数据存在时保留原工作区，可显式体验示例。
- 真实仓库集成覆盖：确认生成模板时按旅行时长筛选；模板失败不落确认；手工日程在重新确认与约束变化后保留；多个成员交通覆盖写入正确成员；缺省交通与 null 无变化时不增约束/旅行版本；日程使用规划基准并替换活动分项。
- 财务域验证整数分、自定义合计、仅参与人承担、非参与垫付人、尾差确定分配、余额和零、部分转账及结算锁；UI 回归用 100 元分给 3 人得到 33.34/33.33/33.33 元，垫付人为第 4 人，记录 1 元转账后锁定，再撤销全部记录恢复修改。
- 浏览器：示例补齐意向→确认→添加手工活动→预算超限提示→账本记账→部分结算→撤销→刷新。另测无确认的空旅行首条安排显式指定日程范围，不自动采用整个搜索窗口。
- 邀请与反馈使用独立浏览器上下文：邀请 payloadId 与登记一致，不含其他成员；接收设备没有原旅行；填写预算和日期、生成反馈；组织者预览不写入，确认应用后预算从 1600 变为 1700 元；重复反馈不增加 revision。仓库测试另验证打开其他旅行时仍提交到反馈目标，以及事务内重复反馈返回原值。
- 备份与恢复使用独立上下文：下载真实 JSON 文件→同 ID 覆盖→财务数据一致→恢复覆盖前版本→另存副本重新映射 ID 并清空意向/确认/邀请。覆盖与恢复均原子保留恢复副本。
- 公开快照：链接不含成员名单、备注或实际账目；隔离设备打开和刷新只读，不生成原旅行；显式另存后新旅行无成员、账本、意向或确认，保留公开日程并生成新 ID。
- 存储测试覆盖命令幂等、旧 revision、两个连接并发、事务中止、模拟配额失败、损坏 JSON 原文保留、原子覆盖/恢复、最多 3 副本、容量上限、命令历史跨覆盖保留、旧连接升级关闭、临时模式与 BroadcastChannel。
