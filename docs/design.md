## 0. 给实施智能体的说明

### 0.1 本文做什么

重写“同路 · 毕业旅行”的视觉语言、页面骨架和基础组件规范，使四个工作区与三个外部页面看起来是同一个产品：层级清楚、有节制的精致感，用户一眼知道“现在在哪、缺什么、下一步点哪里”。

本文只规定**界面层**。不改变业务规则、领域代码、数据结构、路由、存储和分享协议。

### 0.2 文档优先级

| 内容 | 以谁为准 |
| --- | --- |
| 功能范围、业务规则、路由、数据与分享协议、弹层清单、状态与错误恢复 | PRD / BUSINESS_RULES / architecture / pages.md |
| 色彩、字体、间距、圆角、阴影、动效、组件外观、页面骨架与排版 | **本文**（取代 pages.md §13 的视觉规格，以及 pages.md 各页中的布局示意图） |
| 性能预算、CLS 占位、可访问性底线 | 本文 §8 与 HANDOFF，二者均为硬约束 |

冲突处理：业务与数据正确性 > 本文 > pages.md 的旧视觉。涉及功能含义的冲突，先提出，不要静默取舍。完成后建议在 AGENTS.md 的“按需阅读索引”增加一行：`编写或调整界面视觉 → docs/design.md`，并在 pages.md §13 顶部加一句“视觉规格已由 design.md 取代”。

### 0.3 硬约束（不得破坏）

1. 不改 `src/domain`、`src/infrastructure`、`src/contracts`、命令与路由；页面仍只调用 `execute`，不直接写库。
2. 不引入运行时远程字体、图库、CDN、动画库、UI 框架。本文不需要任何新依赖，全部用 CSS 实现。
3. 图标仅用 `lucide-react` 具名静态导入（§5.14 列出了已核对存在的图标）。
4. 性能：首屏 JS gzip ≤ 200 KiB、CSS gzip ≤ 40 KiB、首屏传输 ≤ 700 KiB、单图 ≤ 150 KiB，LCP ≤ 2.5 s、CLS ≤ 0.1。
5. 视口覆盖 375 / 768 / 1440 px，手机无整页横向滚动。
6. 保持 e2e 依赖的可访问名称与结构（§9）。
7. 图片只作图，不承载金额、按钮与正文；示例、估算、本地保存、只读等标记必须继续存在且措辞不变（§2.2 第 5 条）。

## 1. 现状诊断（基于对当前代码与截图的实际阅读）

### 1.1 要保留的

- 业务层稳定，分层清楚；对话框焦点管理、保存状态、错误恢复已经做得扎实。
- 文案诚实（“示例旅行 · 成员与账目均为虚构”“内置估算，非实时报价”“示意图”），不伪造在线状态。
- 本地目的地插画、Lucide 图标、HashRouter、无远程资源的工程约束。
- 极强的性能与 CLS 意识（HANDOFF 里的占位尺寸与图片预加载）。

### 1.2 要解决的

| # | 问题 | 证据 | 后果 |
| --- | --- | --- | --- |
| 1 | **没有统一页面骨架** | 小队是“带图横幅 + 表格”，方案是“筛选条 + 卡片”，日程是“标题 + 副标 + 时间线”，账本是“标题 + 标签页 + 大数字”，四页头部形态各异 | 每换一页都要重新找标题、主操作和状态，观感零散 |
| 2 | **色彩单一且硬编码** | `tokens.css` 仅 11 行；近似的鼠尾草底色就有 `#eaf0e9 / #eaf0e6 / #e5ecdf / #eef3e9` 四种；告警底色 `#fff4f0 / #fff0ec / #fff1d7 / #fff5df` 各用各的 | 整站只有“一种绿”，层级与状态靠文字色，难以统一调整 |
| 3 | **“分隔线列表”铺满全站，没有面与层级** | 成员、日程、费用都是细线分隔的行，页面各块权重相同 | 看不出重点，也显得平，缺少精致感 |
| 4 | **手机小队页重复且冗长** | 375 px 下 6 位成员约占 1,300 px，每人一整块，附两个按钮 | 信息密度低、操作重复，滚动成本高 |
| 5 | **状态分散，没有整体进度** | 保存状态在顶栏；示例标记是独立的细行；确认状态是方案 `h1` 里的小标签；导航项没有任何状态 | 用户不知道现在处于“小队 → 方案 → 日程 → 账本”的哪一步，也不知道下一步 |
| 6 | **外部页面游离于设计系统之外** | `SnapshotPage.tsx` 大量内联样式，圆角 16 px 而工作台是 4–8 px，用 “✓” 字符代替图标 | 接收者看到的像另一个产品 |
| 7 | **标题字体回退不稳** | `--font-heading` 回退链含 `SimSun / STSong`；Windows 没有 Songti SC，大字号会落到 SimSun，且标题加了 `.04em–.08em` 字距 | 在 Windows 上标题显得陈旧、粗细不均，这是“呆板”感的来源之一 |
| 8 | **交互反馈单薄** | 只有 160 ms 颜色过渡，hover 仅换底色，选中、进行中、完成缺少层次 | 缺少“被回应”的质感 |
| 9 | **手机主操作不可达** | 主按钮在页面流内，滚动后消失 | 长列表里要回顶部才能添加 |

## 2. 设计概念：同路手账

### 2.1 一句话

**一本被翻开的旅行手账**：暖白的纸、深松绿的墨、票根的边、一枚朱砂的印。安静、清晰、有秩序，有旅行感但不幼稚。

| 隐喻 | 落到界面 |
| --- | --- |
| 纸 | 暖白画布 `--canvas` 承载整页，白色面 `--surface` 承载主数据 |
| 墨 | 深松绿文字与主色 `--pine-700`，取代“冷灰 + 单色绿” |
| 票 | 方案卡片与结算行使用“票根”边缘（打孔缺口 + 虚线），全站只用这一种装饰 |
| 印 | 朱砂 `--seal` 仅用于品牌标记与“示意图”戳记，不承担语义 |

**反目标**：不做渐变英雄区、毛玻璃、emoji、卡片套卡片、满屏投影、营销文案、装饰性插画堆叠。

### 2.2 六条原则（评审与实现都用它们裁决）

1. **一页一主角**：每页有且只有一个视觉焦点和一个实心主按钮。
2. **状态外露**：当前阶段、缺什么、下一步，在导航、页头、行内就能看见，不靠读说明。
3. **用空间分组，不用框**：同级内容靠间距与细线分组；“面（Sheet）”只用于可操作的主数据块，且**绝不嵌套**。
4. **数字是主角**：金额、人数、日期是页面里最大的字，用等宽数字；标签退后一级。
5. **诚实**：示例 / 估算 / 本地保存 / 只读，用固定的“Chip + 图标”语言表达，措辞沿用现有文案；图片只作图。
6. **同一件事，同一种长相**：成员永远是 Avatar，金额永远是 Figure，状态永远是 StatusChip，在所有页面一致。

### 2.3 三层视觉结构

```text
L0 画布 canvas      页面底色，暖白纸色
L1 面   sheet       白色、1px 细线、12px 圆角、极轻阴影；承载一个完整的主数据块
L2 凹槽 inset       canvas-sunken 底色；表头、摘要井、选中背景，无边框
```

禁止出现 L1 套 L1。需要子分组时用标题 + 细线，或 L2 凹槽。

### 3.2 颜色使用比例与规则

- **面积**：画布与白色面约 85%，松绿（主按钮、选中、链接、进度）约 10%，语义色约 4%，朱砂 ≤ 1%。
- 一屏内实心主按钮最多一个；其余用描边或文字按钮。
- 语义色必须“颜色 + 图标 + 文字”三者同在，不得只靠颜色区分冲突、完成与待处理。
- `--ink-300`、`--seal` 不得用于任何文字。
- 深色模式：本版不做，`color-scheme: light`。

### 3.4 字体与排版规则

- 正文基准 **15 px / 24 px**（现为 14 px）；表格与列表内数据 14 px；最小字号 12 px。手机输入控件 16 px，避免聚焦缩放。
- H1 使用 `--text-display`，字距 0；**移除现有 `.04em / .08em` 的标题字距**。手机 H1 为 30/38。
- 衬线（`--font-display`）只用于：H1、目的地名（`--text-title-lg`）、品牌字标。其余全部无衬线。没有衬线字体的设备自动回退到无衬线 700，不得为此引入字体文件。
- 所有金额、日期、人数、百分比使用 `font-variant-numeric: tabular-nums lining-nums`；金额右对齐。
- 一行一意：行内标题 16/24，辅助行 12/20 或 14/20 ink-500，不再叠第三级。
- 中文不使用斜体、不使用全大写；英文 eyebrow 不需要，全站 eyebrow 一律中文。
- 文案语气：陈述事实，少用感叹与引导语；按钮用动词短语（添加成员、记一笔、记录已转账）。

### 3.5 间距与节奏

- 页面区块之间：桌面 32 px，手机 24 px；区块内标题到内容 16 px；同组条目之间 12 px。
- 面（Sheet）内边距：桌面 24 px，手机 16 px。行高度：列表行最小 56 px，紧凑行最小 44 px。
- 所有内容共用一条**左对齐轴线**：页头标题、统计条、面的左缘对齐，不得出现缩进的孤立块。

### 3.6 图标

沿用 Lucide：默认 20 px、线宽 2、`currentColor`；辅助 16 px；≥ 32 px 的装饰图标线宽 1.5。装饰图标 `aria-hidden`；仅图标的按钮必须有 `aria-label` 且点击区 ≥ 44 × 44 px。导航与状态图标集中放在 `src/components/icons.ts`（具名导出，禁止 `import *`）。

### 4.3 页面骨架（四个工作区必须一致）

每个工作区按下列顺序，缺一不可、不得换位：

```text
1. Eyebrow       仅示例旅行显示“示例旅行 · 成员与账目均为虚构”（带小圆点），否则整行不渲染
2. PageHeader    H1（含必要状态 Chip）+ 一句状态副标题（≤ 1 行）｜ 主操作（右）
3. StatStrip     一个面，3–4 格关键数字（手机 2 × 2）
4. 主内容 + 辅助  8/4 栅格；辅助区只放“下一步 / 待补充 / 预算摘要”这类帮助决策的内容
5. 页尾提示      估算来源、本地保存说明等必要说明，一行，12/20 ink-500
```

- 每页恰好 **一个 `<h1>`**；h1 文本沿用现有（小队 / 方案 / 日程 / 账本），方案页 h1 内含状态 Chip（如“已确认”），见 §9。
- 主操作为实心主按钮，页内唯一；其余动作为描边或文字按钮。
- 页头副标题用一句话说明“现在是什么状态”，例如“5 人资料完整，周予安还缺预算”，由现有数据拼接，不写营销句。
- 区块之间只用间距分组，**不再叠加多条通栏细线**；细线只出现在列表行之间和面的头部。

### 4.4 导航状态信号（Nav Signals）

让导航本身回答“哪里需要我”。每个导航项最多一条副文字，规则与来源如下（均来自已有选择器，**不得新增业务算法**；取不到就不显示，绝不伪造）：

| 工作区 | 副文字示例 | 来源 | 样式 |
| --- | --- | --- | --- |
| 小队 | `5/6 资料完整` | `getMemberProfileStatus` 统计 | 全部完整用 success，否则 warning 小点 |
| 方案 | `筹备中` / `已确认` / `待重新确认` | `getConsensusStatus` 与 `trip.confirmation` | 对应 Chip 同色小点 |
| 日程 | `3 天` 或 `2 项待估算` | 日程预算摘要的既有结果 | 有待估算用 warning 小点 |
| 账本 | `已结清` / `未结清` | 既有余额与结算结果 | 未结清 warning 小点 |

- 手机底部导航不放副文字，只在图标右上放 8 px 状态小点（有待处理才显示）。
- **不得改变导航链接的可访问名称**：e2e 以 `getByRole('link', { name: '日程', exact: true })` 精确匹配。因此副文字与小点都要 `aria-hidden="true"`，其文字通过链接的 `aria-describedby` 提供给读屏用户，**不能**写进链接的 `aria-label` 或可见文本节点的无障碍名称里；`nav[aria-label="工作区"]` 内仍恰好 4 个链接。
- 这些元素的尺寸固定，数据到达前后不改变导航项高度（遵守 HANDOFF 的 CLS 教训）。
- 该项属 **P1**（见 §10），不阻塞页面重写；未实现时导航保持无副文字。

### 4.5 面（Sheet）与列表的使用规则

- 一个页面的主数据只放进 1–2 个 Sheet：小队“成员名册”、方案“候选卡片组”（卡片本身是 Ticket，不再套 Sheet）、日程“时间线”、账本“账目 / 结算列表”。
- Sheet 之外只有：页头、统计条、辅助区块。辅助区块也是 Sheet，但不得与主 Sheet 嵌套。
- 表格在桌面使用真实 `<table>`（保留语义）；手机转为行列表，**不使用整表横向滚动**。
- 辅助区在桌面粘性定位（`position: sticky; top: calc(var(--topbar-h) + 24px)`），平板与手机取消。

## 5. 基础组件规范

新增组件放入 `src/components/ui/`（可拆文件，保持从 `index.tsx` 统一导出）；组件样式写在 `src/styles/components.css` 或各自的 CSS Module。**跨模块修饰基础组件时用 `:global(.xxx)`**（HANDOFF：CSS Modules 会改写类名）。

### 5.1 Button

| 变体 | 外观 | 用途 |
| --- | --- | --- |
| primary | 底 `--pine-700`，字白，悬停 `--pine-800`，无阴影；按下 `translateY(1px)` | 页内唯一主操作、表单提交 |
| secondary | 底 `--surface`，1 px `--line-strong` 描边，字 `--pine-700`；悬停底 `--pine-50`、描边 `--pine-200` | 次要操作 |
| ghost | 透明，字 `--ink-700`；悬停底 `--pine-50` | 行内操作、菜单项 |
| danger | 描边 `--brick-700` + 字 `--brick-700`；**仅在确认弹窗中**用实心 `--brick-700` | 删除、撤销 |

- 高度一律 **44 px**（触控下限），内边距 8 × 16，圆角 `--radius-control`，字 `--text-data` 600，图标 20 px，图标与文字间距 8 px。
- 图标按钮 44 × 44，必须有 `aria-label`。
- 状态：hover、active、`:focus-visible`（用 `--focus-ring`）、disabled（`opacity: .48`，原因在附近可见）、loading（左侧 `LoaderCircle` 旋转 + 文字不变，宽度不跳动）。
- 保留现有 `Button` 的 `variant` API（`primary | secondary | danger | ghost`），不要改名。

### 5.2 Field（输入、选择、文本域）

- 标签在上，14/20 600；辅助说明 12/20 ink-500；错误信息 14/20 `--danger-fg`，前置 `CircleAlert` 16 px，并通过 `aria-describedby` 关联。
- 控件高 44 px（文本域最小 88 px），圆角 8，1 px `--control-border`，底 `--surface`；悬停描边 `--ink-500`；聚焦描边 `--pine-700` + `--field-ring`；错误描边 `--brick-700`。
- 手机字号 16 px。表单内两栏仅在 ≥ 768 px 的弹层里使用。
- 分组用 `<fieldset>`：顶部 1 px `--line`、`legend` 14/20 600，不加外框。

### 5.3 Chip 与 StatusChip

- **StatusChip**：高 24、`--radius-pill`、内边距 0 10、12/20 500，**左侧 14 px 图标必有**。五种语气：neutral（`--canvas-sunken` / `--ink-700`，图标 `CircleDashed`）、success（`CircleCheck`）、info（`Info`）、warning（`Clock` 或 `TriangleAlert`）、danger（`CircleAlert`）。
- **TagChip**（偏好标签，可选）：高 44（可点击时）/ 28（只读时），圆角 8，1 px `--line-strong`；选中为 `--pine-100` 底 + `--pine-700` 字 + 前置 `Check` 14 px，**不能只靠底色表示选中**。

### 5.4 Avatar

- 圆形，32（行内）/ 40（头部）/ 28（MemberStrip）；内容为姓名首字，字号 = 直径 × .5，`--font-sans` 600。
- 颜色按成员**顺序取模**从 `--avatar-1..6` 取，同一成员在所有页面颜色一致；`aria-hidden`，姓名始终以文字出现在旁边。

### 5.5 Sheet

```css
.sheet { background: var(--surface); border: 1px solid var(--line); border-radius: var(--radius-card); box-shadow: var(--shadow-1); }
.sheet-head { display: flex; align-items: center; justify-content: space-between; gap: 16px; padding: 20px 24px 16px; }   /* 标题 --text-title */
.sheet-body { padding: 0 24px 24px; }                                                                                     /* 手机 16 */
```
- 头部与列表之间 1 px `--line`。**禁止嵌套 Sheet**。

### 5.6 StatStrip 与 Stat

- 一个 Sheet，内部 3–4 个 Stat 等分，格间用 1 px `--line` 竖线（手机 2 × 2，用横线与竖线分隔）。
- Stat：标签 12/20 ink-500 → 数字 `--text-figure-lg` ink-900 → 副行 12/20（图标 + 状态文字，可空）。
- 数字单位（人、笔、/人）用 `--text-caption`，与数字基线对齐。
- 没有值时显示“待补充”（ink-500），不显示 0 或破折号。

### 5.7 PageHeader

- 结构：`eyebrow? / h1 + 副标题 / actions`。桌面 h1 与主操作同一行底对齐；手机 h1 一行，副标题 12/20，操作区折到下一行。
- **手机主操作固定**：对“添加成员 / 添加安排 / 记一笔”三个创建类主按钮，在 < 768 px 用 CSS 将**同一个按钮元素**设为 `position: fixed; right: 16px; bottom: calc(var(--tabbar-h) + 16px + env(safe-area-inset-bottom)); z-index: var(--z-fab); box-shadow: var(--shadow-2)`，圆角 `--radius-pill`，保留文字。**不得复制第二个按钮**（e2e 要求按钮唯一，见 §9），并给内容区底部预留 `calc(var(--tabbar-h) + 88px)`。

### 5.8 Table 与 RosterRow

- 桌面表头：`--canvas-sunken` 底（L2 凹槽）、12/20 ink-500 500，无描边；行高 ≥ 56，行间 1 px `--line`，悬停底 `--pine-50`，圆角只在首尾单元格外缘 8 px。
- 数值列右对齐、等宽数字；文字列左对齐；操作列右对齐，使用 ghost 按钮与图标按钮，**保持现有可访问名称**（如“编辑 林知夏”“邀请 林知夏 填写”“删除 林知夏”）。
- 手机行列表：首行 Avatar + 姓名 + 右侧一个“更多”菜单或编辑；次行最多两列信息；“邀请”“删除”进入行菜单，**不再每人两个并排大按钮**。

### 5.9 Ticket（票根）与 PlanCard

```text
┌──────────────────────────────────┐  外框 radius 16，1px line，shadow-1，overflow hidden
│        目的地图（3:2，不叠字）      │  src 480；srcset 960；示意图戳记见下
├──────────────────────────────────┤
│ 青岛                          01  │  h2（--text-title-lg）｜排序号 12/20 ink-500，不在 h2 内
│ 12/09 – 12/11 · 3 天 2 晚          │  --text-data ink-500
│ ¥1,280 – 1,380 / 人               │  --text-figure-lg；“/ 人”为 caption
│ 个人基准估算范围，非实时报价        │  caption ink-500
◖ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ┈ ◗  票根线：1px dashed --line-strong，两端 16px 缺口圆（底色 --canvas）
│ MemberStrip（成员适配）            │
│ 时间 6/6 · 预算 5/6               │  --text-data；冲突项 danger，未知项 warning，通过项 success；每项配图标
│ ▬▬▬▬▬▬▬▬▬░░  SegmentBar          │
│ 赞成 4 · 可接受 1 · 待反馈 1       │

└──────────────────────────────────┘
```
- 缺口用两个绝对定位的 `::before/::after` 圆（16 px，`background: var(--canvas)`）实现；外框 `overflow: hidden`。
- 悬停：`translateY(-2px)` + `--shadow-2`，180 ms；`prefers-reduced-motion` 下取消位移。
- 图片错误或未载入：固定比例的 `--pine-50` 底 + 居中的目的地名（文字，不是图片），保持布局不动。
- “示意图”戳记：图片右下角 12/20 小标，底 `--surface` 92% 不透明，字 `--seal`，描边 1 px `--seal`（这是**披露标签**，允许叠在图上；除此之外图上不得有文字、金额或按钮）。
- 图片 `width/height` 或 `aspect-ratio` 必填；首屏以外 `loading="lazy" decoding="async"`。
- 结算建议行（账本）复用票根语言：左右缺口 + 虚线，见 §6.5。

### 5.10 MemberStrip

- 一排 28 px Avatar，间距 6 px；每个头像右下有 12 px 状态角标：通过 `Check`（success）、冲突 `TriangleAlert`（danger）、未知 `Minus`（warning）。头像外圈 2 px 描边同色。
- 无障碍：`<ul aria-label="成员适配">`，每个 `<li>` 含视觉隐藏文字，如“周予安：预算超出 ¥180”。
- 超过 8 人显示前 8 个 + “+N”文字，其余仅在视觉隐藏列表中保留。
- 数据来自 `services.planning.getPlanEvaluations` 的逐成员结果（详情抽屉“成员适配”用的就是同一数据）。**若卡片需要的字段不在返回值里，不得在 UI 复算**；应在 planning 域暴露只读选择器并补测试。

### 5.11 SegmentBar 与 DivergingBar

- **SegmentBar**（意向分布）：高 8，圆角 pill，分段 `--pine-700`（赞成）/ `--sea-600`（可接受）/ `--brick-700`（不参加）/ 斜纹灰（待反馈：`repeating-linear-gradient(45deg, var(--line-strong) 0 4px, transparent 4px 8px)`）。条本身 `aria-hidden`，语义由下方图例文字承担（颜色点 + 文字 + 数字）。
- **DivergingBar**（账本余额）：每行“姓名 | 条 | 金额文字”。中轴居中，应收向右 `--pine-700`，应付向左 `--brick-700`，条长按本组最大绝对余额归一，非零最小 2 px；金额文字 `应收 ¥155.00 / 应付 ¥55.00 / 已结清` 右对齐；条 `aria-hidden`。

### 5.12 SegmentedControl / Tabs

- 轨道 `--canvas-sunken`，圆角 10，内边距 4；选中滑块 `--surface` + `--shadow-1`；每项高 40、字 `--text-data` 600，选中字 `--pine-700`，未选 `--ink-700`。
- 用于账本“账目 / 结算”时必须保持 `role="tablist" / "tab" / "tabpanel"` 与 `aria-selected`；用于时长（3/4/5 天）等筛选时用 `role="radiogroup"`。
- 键盘：左右方向键切换，Home/End 跳首尾。

### 5.13 Dialog / Drawer / BottomSheet / Menu / Notice / EmptyState / Skeleton

- **Dialog**：宽 `min(560px, 100% - 32px)`，圆角 16，`--shadow-pop`，遮罩 `rgb(16 58 49 / .45)`（**不加 backdrop-filter 模糊**）。头部标题 `--text-title`（无衬线）、右侧 X；底部操作栏固定，背景 `--canvas`，上沿细线。
- **Drawer**：右侧，宽 `min(640px, 100%)`（方案详情 720），直角贴边，其余同 Dialog；进入动画 `translateX(24px) → 0` + 透明度，180 ms。
- **手机**：短确认对话框改为**底部面板**（圆角 `16px 16px 0 0`，最大高 90dvh，顶部 36 × 4 px 装饰把手 `aria-hidden`）；长表单与详情仍是**全屏**，头部与底部操作栏吸附，正文滚动。继续使用原生 `<dialog>` 与现有焦点返回逻辑（`returnFocusRef`），不要重写。
- **Menu**：保留 `<details>/<summary>`；弹出层圆角 12、`--shadow-pop`、内边距 8，项高 44、图标 20 + 文字；危险项上方加 1 px 细线。**全页面只能有一个 `<summary>`**（见 §9）。
- **Notice**（取代 `.error-notice / .banner / .demo-notice`）：`tone = info | warning | danger | success`，左侧语气图标 + 文字 + 可选操作；底色用对应 `*-bg`，**无边框，左侧 3 px 同色竖条**。danger 用 `role="alert"`，其余 `role="status"`。示例旅行提示用 info 语气的行内小圆点版本，措辞不变。

## 7. 动效与交互

- **原则**：动效是反馈，不是装饰；只动 `opacity` 与 `transform`（少量 `background-color`、`border-color`），不动布局属性，不阻塞操作，不用来遮盖加载。
- **时长**：微交互（悬停、按下）120 ms；状态切换、展开、抽屉 180 ms；底部面板进入 280 ms。曲线统一 `--ease-out`。
- **清单**：

| 元素 | 效果 |
| --- | --- |
| 按钮 | 悬停换色；按下 `translateY(1px)`；loading 时左侧图标旋转 |
| PlanCard / Ticket | 悬停 `translateY(-2px)` + `--shadow-2` |
| 列表行 | 悬停底 `--pine-50`；展开时 Chevron 旋转 180° |
| SegmentedControl | 滑块 `transform` 平移 |
| Drawer | `translateX(24px)→0` + 渐显；手机全屏版为 `translateY(16px)→0` |
| BottomSheet | `translateY(100%)→0`，280 ms |
| 保存成功 | 图标由旋转切换为勾，**不做庆祝动画** |

- **禁止**：数字滚动计数、滚动入场、视差、骨架闪光扫过、页面切换转场、自动轮播。
- **减少动态效果**：`@media (prefers-reduced-motion: reduce)` 下取消所有位移与旋转（保持颜色变化），沿用现有全局规则。
- **焦点**：所有可交互元素用 `--focus-ring`（2 px 留白 + 2 px 松绿），不得被 `overflow: hidden` 裁掉（必要时加 `outline-offset` 或内缩）。
- **悬停不是唯一入口**：所有悬停才出现的信息，键盘与触屏也必须可达。

## 8. 可访问性与性能底线

### 8.1 可访问性

- 文字对比 ≥ 4.5:1，控件边界与图形 ≥ 3:1（§3.3 已核对；新增颜色先核对）。
- 颜色不独自承担含义：冲突、完成、待处理、选中一律“颜色 + 图标 + 文字”。
- 触控目标 ≥ 44 × 44 px；手机输入 16 px。
- 键盘：Tab 顺序与视觉顺序一致；SegmentedControl 方向键；Dialog/Drawer 保持现有焦点陷阱与 `returnFocusRef`；Escape 关闭，有未保存修改先确认。
- 语义：每页一个 `h1`；表格用 `<table>`；条形图类装饰 `aria-hidden`，同义文字必须在页面里；状态用 `role="status"`，错误用 `role="alert"`。
- 跳转主内容链接保留；`main#main` 保持 `tabIndex={-1}`。
- 减少动态效果、200% 缩放、文字间距加大时布局不重叠。

### 8.2 性能与布局稳定

- 预算见 §0.3。重写后必须重跑 `check:bundle-size`；CSS gzip ≤ 40 KiB，因此**共享样式写一次**（令牌 + 组件类），页面 CSS 只写版式，不重复定义按钮、Chip、Sheet。
- **不新增图片**。首屏仍只有“小队”的苏州插画（240 / 480）；方案页图片按可见范围加载；其余视觉用 CSS 与 Lucide 图标完成。
- **CLS 占位尺寸保持**（来自 HANDOFF 的实测教训）：旅行选择器加载占位 44 px 高；手机保存状态行 28 px；顶部工具区最小宽 162 px。新增的统计条、导航副文字、日期导航、规划条摘要都要**先占位、后填数**，且占位与完成态同高。
- 不使用 `backdrop-filter`、大面积渐变、`filter: drop-shadow`、会触发重排的动画。
- 不使用 CSS `@import`、`@font-face`、远程 `url()`；背景图一律不用。
- 骨架与 Suspense 回退与最终元素同形同高，避免跳动。
- 改版后复测 `benchmark:browser`（LCP ≤ 2.5 s、CLS ≤ 0.1，三轮最差值）并写入 ACCEPTANCE.md；本文不给出任何已测数值。

## 9. 不得破坏的契约（来自现有 e2e 与 HANDOFF）

以下条目由阅读 `tests/e2e/full-flow/*.spec.ts`、`playwright.config.ts` 与 HANDOFF.MD 得出。e2e 在 375 / 768 / 1440 三个视口都会运行，所以**三个视口的 DOM 都要满足**。若确需改变，必须同步更新 e2e 并说明理由。

| # | 契约 | 违反的后果 |
| --- | --- | --- |
| 1 | 页面里**只能有一个 `<summary>`**（顶栏“更多”菜单）；折叠、行菜单一律用 `button[aria-expanded]` | `page.locator('summary').click()` 因多个匹配而失败 |
| 2 | 每页恰好**一个 `h1`**，文本分别含 小队 / 方案 / 日程 / 账本；方案页 h1 含“已确认”等状态词；空状态 h1 为“出发，从一支小队开始” | `getByRole('heading', { level: 1 })` 严格匹配失败 |
| 3 | **其他标题不得与工作区名完全同名**（Sheet 标题不能叫“账本”“日程”等），因 `getByRole('heading', { name: '账本', exact: true })` | 匹配到多个标题 |
| 4 | 导航：`nav[aria-label="工作区"]` 内恰好 4 个链接，名称精确为 小队/方案/日程/账本，当前项 `aria-current="page"`；副文字与小点不进入可访问名称 | 链接名称或数量断言失败 |
| 5 | `select` 的可访问名称为“选择旅行”（`combobox`），内容含旅行名 | 重命名/刷新断言失败 |
| 6 | 保存状态：`role="status"` + `aria-label="保存状态"`，任一视口恰好一个**可见**，文字含“已保存到此设备 / 尚未保存 / 其他标签页已更新 / 临时体验 · 刷新后丢失” | 状态等待超时 |
| 7 | 主操作与菜单按钮名称保持：添加成员、导入反馈、添加安排、记一笔（有结算时 `disabled`）、记录已转账、记录此笔转账、撤销全部结算记录、确认撤销、查看方案、代录意向、赞成、确认此方案、重命名、完整备份、删除旅行、确认删除、创建旅行、保存名称、重试保存、导出当前内容、重新载入、生成邀请链接、导入反馈、预览导入、应用到此设备、下载备份文件 等 | 按名称定位失败 |
| 8 | 主操作按钮在 DOM 中**只存在一份**（手机浮动按钮用 CSS 定位同一元素，不复制） | `记一笔` 严格匹配到两个 |
| 9 | 成员行按钮名称：`编辑 X`、`邀请 X 填写`、`删除 X`；复选框名称为成员姓名；`group` 名称 `X方案适配`、`X意向` | 定位失败 |
| 10 | PlanCard：`article` > `h2` 目的地名精确匹配；卡片文本含 `时间 6/6` 这类连续文本；`<h2>` 内不得夹排序号 | 卡片查找失败 |
| 11 | 账本：标签页 `role="tab"` 名称“账目/结算”；总览整句 `实际支出 ¥490.00 · 3 笔` 为连续文本 | 文本断言失败 |
| 12 | 文案保留：“日程调整后超出成员预算”“该反馈已应用过，不会再次写入。”“临时体验模式：”“示例旅行 · 成员与账目均为虚构”“内置估算，非实时报价”“只读快照”“生成后不会自动更新” | 断言或诚实标识缺失 |
| 13 | `document.documentElement.scrollWidth ≤ innerWidth`（三视口无横向溢出）；浮动按钮、粘性栏不得造成溢出 | 溢出检查失败 |
| 14 | 原生 `<dialog>` + 现有焦点返回；`getByRole('dialog')` 同时只有一个打开 | 键盘与关闭断言失败 |
| 15 | HANDOFF：跨模块修饰基础组件用 `:global(.field)` / `:global(.button)`；新文件 UTF-8 无 BOM；重建 `dist` 后刷新预览页；Windows 用 `npm.cmd` | 样式不生效、补丁失败 |
| 16 | 首屏小队图的 `<picture>`、尺寸、`fetchpriority="high"` 与 HTML 预加载链路保持（如需移除，须同步改预加载逻辑并复测 LCP） | LCP 回退 |
