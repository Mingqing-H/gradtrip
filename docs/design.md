## 外壳

- 浅色窄侧栏，只有品牌及小队、方案、日程、账本四项。选中项淡紫底，不重复展示导航副标题、阶段文字或状态小点。
- 顶栏为旅行切换、一次“示例”标记、真实本地保存状态、分享、更多。示例标记的提示说明成员与账目虚构。
- 保存中、失败、冲突、临时模式仍使用真实状态；不出现云端或实时同步暗示。
- 手机顶部保留短状态行；三类新增主按钮使用同一 DOM 元素固定到底部导航上方。
- 弹层、外部分享页跟随相同色彩与字体，继续保留既有焦点与错误处理。

## 小队

桌面为三列成员卡 × 多行，右侧 280 px 旅行装备插画与共同日期。每张卡依次为：姓名首字头像及可编辑姓名、更多菜单、大号预算上限、出发地、完整首段日期、偏好。邀请与删除放入成员菜单。仅缺资料时显示补充提示，不为每个人重复“资料完整”。

共同日期来自现有规划服务，仅资料完整且存在共同出发日时展示首个有效出行区间。未知资料和无共同日期分别显示“待补资料”“暂无共同日期”，不能宣称全员可行。成员原始可用日期仍保持真实值；多段日期在编辑中完整查看。

平板两列、手机两列紧凑卡片；辅助插画与日期移至成员之后。空状态、20 人限制、受账目引用的删除限制保留。

## 方案

- 页头只有标题、候选与全员可行数量、唯一“生成方案”主操作。
- 紧凑筛选行含出发日期、时长、调整日期及一次“内置估算，非实时报价”。搜索窗口在调整日期后展开；修改草稿后必须显式生成才应用。
- 桌面横向方案行：写实生成景观 → 城市、日期、人均区间 → 时间/预算人数及进度 → 意向与查看方案。苏州、青岛、厦门使用很浅的绿、蓝、暖白辅助底。
- 不重复显示每人成员头像，逐人成员适配保留给读屏与详情。时间/预算人数必须区分冲突、未知，不能把单项通过写成整体“全员可行”。
- 投票不绕过硬约束。详情内继续提供估算调整、意向代录、确认、分享方案及日程跳转。
- 手机为缩略图与金额双列，约束与意向在下方；无全页横向滚动。

## 日程

桌面三列按天并排；超过三天继续排列，不删除后续天。每列页头有日期和小型 3D 插画，下面是时间、活动、类别与费用归属、操作菜单。备注通过操作菜单中的“查看备注”阅读，不在时间线上铺长段落。编辑、上下移动、删除、单日添加继续可用。

底部一条活动估算带：已知金额、人均单位、未知项、已含于方案的项数；方案基准与逐人差额在“预算明细”内。预算超限、日期范围问题与时间重叠保持可见。

平板、手机改为纵向，并提供按天跳转。活动展示顺序继续遵守领域层“有时间在前、无时间随后”的规则，不能为照搬示意图而改写排序或重复费用。

## 账本

默认展示选稿对应的结算子视图，账目子视图完整保留。桌面双栏，左侧成员的已垫付、当前余额、展开明细；右侧转账建议、结算历史及小型笔记本插画。金额右对齐、等宽数字，应收与应付同时使用文字和色彩。结算记录折叠，撤销入口仅有有效记录时出现。

“记录已转账”只记录线下确认。锁定费用、撤销规则和确认对话框继续存在。手机上下排列，表内不引入横向滚动；新增费用、参与人、自定义金额与分摊预览完整可用。

## 素材与性能

详见 [v3 素材记录](./assets/SOURCES-v3.md)。插画为独立生成的透明软陶风格位图；六地景观为摄影质感生成图，始终标记“示意图”，不冒充实拍。

Sharp 仅为开发依赖，用于透明留白裁切、尺寸适配和 WebP 压缩。源图和提示词在 docs/assets/generated-v3，原图不进入 dist。目的地继续使用稳定 ID 与 480/960 px 本地资源；插画按实际显示尺寸导出。所有运行时单图 ≤150 KiB。

小队桌面插画仅在根入口/小队路由且宽度至少 1000 px 时预加载；手机下方插画延后加载。图片有明确宽高或比例。不得为视觉改版引入运行时远程图片、字体、UI 框架或动画库。

保留发布门槛：首屏 JS gzip≤200 KiB、CSS≤40 KiB、首屏传输≤700 KiB、LCP≤2.5s、CLS≤0.1、领域最大计算≤50ms。实际结果以 [ACCEPTANCE](./ACCEPTANCE.md) 为准，不能把设计图或构建通过当作性能结论。

## 视觉验收

对比同一 1440×1024 视口；生成稿原像素 1487×1058 统一缩放后，与实现截图并排比较，并检查字体、间距、色彩、图像及文案五项。375/768/1440 px 检查全部四页与主要操作。

允许的差异仅包括：动态示例日期和真实成员资料；真实余额及实际意向；领域排序；按用户要求将目的地卡通景观替换为写实生成图；必要的错误/恢复/估算披露；手机触控尺寸。不能把生成稿上的重复标签、固定数据或云图标原样搬入产品。
