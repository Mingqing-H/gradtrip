# 同路 · 毕业旅行页面与布局设计

版本：MVP v1.0  
日期：2026-11-18  
状态：已按当前实现更新视觉规格；实际验证见 [ACCEPTANCE](./ACCEPTANCE.md)  
依据：[PRD](./PRD.md)、[业务规则](./BUSINESS_RULES.md)、[MVP 开发文档](./MVP_DEVELOPMENT.md)

## 1. 设计目标

用户进入后，能直接回答四个问题：谁一起去、去哪儿、每天做什么、费用怎么算。页面按这四个任务组织，而不是按技术模块展示功能。

- 首次访问打开示例旅行的“小队”页，有本地记录则恢复最近访问工作区。
- 用户创建的旅行与示例使用相同页面结构，示例只增加清晰的演示标记。
- 成员数据、方案差异和实际金额是主要内容；不增加营销首页、宣传标语区或重复的功能介绍。
- 每页顶部有明确的主要操作；必要的辅助操作保留在对应对象附近。
- 时间、预算、意向的冲突要具体到成员，不能只用一个模糊分数概括。
- 本文确定内容层级和推荐布局；金额、版本和确认条件严格遵循业务规则，不因视觉方案改变。

## 3. 统一工作台外壳

### 3.1 桌面布局

```text
┌─────────────────────────────────────────────────────────────────┐
│ 同路     [旅行名称 ▾]                     分享计划   更多 ⋯       │
├────────────┬────────────────────────────────────────────────────┤
│ 小队       │ 页面标题   必要状态                       主操作     │
│ 方案       │                                                    │
│ 日程       │ 当前任务所需的筛选或摘要                           │
│ 账本       │                                                    │
│            │ 主要内容                           可选的辅助区域  │
│            │                                                    │
│            │                                                    │
│ 本地保存   │                                                    │
└────────────┴────────────────────────────────────────────────────┘
```

- 顶栏高至少 76 px，提供旅行切换器、保存状态、分享和更多；品牌位于侧栏顶部。顶栏不再重复当前页面标题。
- 侧栏宽 208 px，深青绿底，四个导航项从上到下对应核心路径，当前项用浅鼠尾草底色与文字共同标识。
- 主内容左右内边距 32 px，1440 px 起为 48 px；含内边距最大宽度 1440 px，区域间距 24 px，内容整体左对齐。
- 页面标题行展示“小队 / 方案 / 日程 / 账本”，右侧放当前页主操作。
- 状态只在需要的位置显示一次。筹备/确认状态主要出现在方案与日程，不在每个模块重复同一横幅。
- 本地保存状态在桌面顶栏、手机顶栏下方展示；文字配合图标反馈。未保存、临时内存模式或版本冲突时升级为页面内可操作提示。
- 更多菜单包含重命名、导入文件、导出完整备份、备份与恢复、删除旅行；示例旅行另有重置示例。
- 旅行切换器展示本地旅行列表与“创建旅行”，不增加独立旅行列表页。

### 3.2 响应式布局

| 视口 | 布局规则 |
| --- | --- |
| >= 1200 px | 208 px 侧栏，列表与辅助摘要可双栏；方案默认两列 |
| 768～1199 px | 侧栏收至 176 px，主内容内边距 24 px；成员以两列平面信息行展示，预算摘要下移，候选在 1023 px 及以下单列 |
| < 768 px | 取消侧栏，顶栏保留旅行切换与更多；底部四项导航，主内容单列，内边距 16 px |

- 手机底部导航高至少 64 px，并计入设备安全区；滚动内容预留导航和固定操作区高度。
- 分享入口在手机顶栏保留，旅行切换器按可用宽度收缩；页内主操作保持可见。
- 全屏编辑表单打开时隐藏工作台底部导航；表单自身有标题、关闭和底部保存操作。
- 外部分享页不显示四项工作区导航，避免接收者误以为拥有原旅行的编辑权限。
- 桌面双栏按实际内容宽度退化，不以强行缩小文字维持布局；375 px 不产生整页横向滚动。

## 4. P01 小队

### 4.1 页面目标与内容顺序

组织者应先看出谁已经填好、谁还缺资料，再直接编辑或邀请。

1. 浅鼠尾草色横幅内展示“小队”、人数、资料完整人数与真实进度条；右侧复用本地苏州园林插画，标注示意图，不暗示已选定目的地。
2. 横幅下方操作行：实色主操作“添加成员”，描边次操作“导入反馈”；不增加成功说明卡。
3. 成员列表：昵称、城市、预算上限、可用日期、偏好和资料状态。
4. 必要时显示一个下一步入口，如“查看方案”；不增加常驻流程教学区。

```text
小队 · 6 人                                      [添加成员]
5 人资料完整                                      导入反馈

成员       出发地    预算上限     可用日期       偏好      操作
林知夏     上海      ¥1,500      未来日期区间   海边      编辑  邀请
陈亦舟     杭州      ¥1,800      未来日期区间   人文      编辑  邀请
周予安     南京      待补充      未来日期区间   城市      补充  邀请
……
```

- 桌面采用列表行，少用六张并排的大头像卡；日期多于一段时显示首段及“另 1 段”，展开可看全部。
- 手机每位成员一条紧凑信息块：首行昵称、姓氏头像与编辑，次行为城市、预算，随后是日期与偏好，邀请放末行。信息块以分隔线组织，不套圆角卡片。
- 预算空值显示“待补充”，明确零预算显示 ¥0；昵称重复时附已有城市信息帮助识别。
- 资料状态文字与对应缺失字段联动；点“补充”直接聚焦第一个缺失字段。

### 4.2 D02 成员编辑

字段顺序：昵称 → 出发城市 → 预算上限 → 可用日期区间 → 偏好。

- 城市支持输入与内置建议，未知城市可保存，交通估算另行补充。
- 日期按区间逐条编辑，最多 5 段；“添加日期段”放在列表下方。
- 偏好为多选标签，未选表示无特别偏好，不做必填红星。
- 底部“取消 / 保存成员”；删除操作在次级菜单，受账目引用时显示具体原因与相关记录入口。
- 修改会使已有共识失效时，在保存区域显示一次“修改后需重新确认方案”，不使用阻断式重复确认。

### 4.3 关键状态

| 状态 | 页面呈现和可执行操作 |
| --- | --- |
| 新建空旅行 | 单一区块“还没有成员”，按钮“添加成员”；次级入口“导入文件” |
| 资料不完整 | 成员行标出缺失内容，允许保存阶段性资料与继续邀请 |
| 达 20 人上限 | 添加操作旁说明人数已满，保留编辑和导出 |
| 反馈已应用 | 对应成员短暂高亮，提示“已应用到此设备”，汇总随数据刷新 |
| 反馈过期 | 在导入预览解释过期，提供“重新生成邀请”，不提供强制覆盖 |

## 5. P02 方案

### 5.1 页面布局

页面以候选比较为主，筛选只保留影响共同出行的输入。

```text
方案               [筹备中 / 已确认 / 待重新确认]

[搜索窗口]  [3 天 2 晚 ▾]  [共同出发日 ▾]      [生成方案]

┌────────────────────────┐   ┌────────────────────────┐
│ 目的地缩略图           │   │ 目的地缩略图           │
│ 青岛                   │   │ 苏州                   │
│ 日期 · 3 天 2 晚       │   │ 日期 · 3 天 2 晚       │
│ ¥1,280～1,380 / 人      │   │ 个人基准估算范围       │
│ 时间 6/6 · 预算 6/6    │   │ 时间 6/6 · 预算 5/6    │
│ 赞成 4 · 可接受 1      │   │ 1 人超预算             │
│ 待反馈 1               │   │ ……                     │
│ [查看方案]             │   │ [查看方案]             │
└────────────────────────┘   └────────────────────────┘
```

- 主操作“生成方案”仅在首次生成或显式重建候选时提交；编辑筛选时显示尚未应用，不偷偷重建导致意向丢失。
- 时间与预算使用紧凑指标行；明确冲突时追加具体人数，未知资料显示“待补充”，不显示为匹配失败。
- 共同日期不足时可另选指定日期查看冲突；不能自动删掉某位成员获得“全员可行”。
- 缩略图是可选的本地目的地图片，固定比例 16:9；图片失效用纯色底与目的地名保留布局。
- 方案卡片两列，手机单列。第一屏能看到筛选和至少一个候选的核心信息，图片高度不抢占操作区。
- 手机已有候选时将筛选收为“日期 · 时长 / 调整日期”操作行，点击展开完整控件；无候选时默认展开。生成成功后收起筛选，让候选回到阅读主线。桌面始终展开筛选。
- 每张卡的估算数值来自个人计算，示意数字不硬编码。卡片不放确认按钮，确认前必须进入详情查看成员条件。
- 所有候选共用一处短说明“内置估算，非实时报价”；详情在金额明细附近保留来源。

### 5.2 D04 方案详情

桌面右侧宽抽屉建议 720 px；宽度不足改为全屏，不把背后的候选列表挤成不可读窄栏。

内容顺序：

1. 目的地、日期、时长、个人估算区间。
2. “成员适配”明细：成员、时间、个人估算/预算上限、差额、当前意向。
3. “费用估算”明细：交通按成员列出；住宿按每晚人均、餐饮按每天人均、活动和机动预算列出。
4. 可折叠的日程模板预览，不与正式日程编辑混淆。
5. 底部确认区域：阻止条件清单或“确认此方案”。

- 明确显示如“林知夏超预算 ¥180”，提供“编辑成员预算”与“调整估算”入口，修改需走表单保存。
- 调整估算在当前详情内切换编辑状态，不能叠加第二个大抽屉。
- 人数少时成员明细全部展开，人数多时内部可滚动；手机按成员分组，避免六列表格横向滚动。
- 缺估算时显示“补充交通估算”，不允许用破折号悄悄跳过费用判断。
- 当前条件不满足时，在确认按钮之前列出具体阻止项，并提供定位入口；不能只出现不可点击按钮。
- 全员条件满足时可确认；已有日程时选择“保留当前日程”或“替换为模板”，默认保留，替换需二次确认。
- 确认成功后停留当前结果，提供“查看日程”，保留返回候选列表的路径。

### 5.3 意向代录和示例视角

- 真实旅行允许组织者在成员行“记录意向”，展开赞成、可接受、不参加三个选项，并注明“根据线下沟通代录”。
- 来源默认折叠在意向明细，主列表只展示当前值；需要追溯时查看来源和记录时间。
- 示例详情额外显示“演示身份：[成员 ▾]”，以当前选中的虚构成员表达意向；不显示虚假在线状态。
- 已失效意向归入折叠历史，当前显示“需重新反馈”，不继续计入赞成人数。

### 5.4 状态与去向

| 状态 | 内容与动作 |
| --- | --- |
| 尚无候选 | 先展示日期输入与“生成方案”，缺成员资料时列出补充入口 |
| 无共同日期 | 显示成员日期冲突，允许另选日期查看；入口“回小队调整” |
| 没有全员可行方案 | 保留候选，按规则排序并具体显示冲突；不显示空白结果 |
| 部分意向待反馈 | 显示待反馈成员，在相应行邀请或代录 |
| 已确认 | 当前卡片有“已确认”，详情展示确认记录和日程入口 |
| 约束改变 | 显示“待重新确认”及变化原因，保留日程，不自动清空用户工作 |

## 6. P03 日程

### 6.1 页面布局

```text
日程        青岛 · 日期范围 · 3 天 2 晚             [添加安排]

Day 1  日期  ──────────────────────────────────────────────
09:30–11:00   抵达与集合        交通       已含于方案      ⋯
14:00–16:30   沿海散步          活动       ¥0 / 人         ⋯
未定时间      老城区参观        活动       ¥45 / 人        ⋯

Day 2  日期  ──────────────────────────────────────────────
……

                                   日程预算摘要（桌面右侧）
```

- 主区域为按天纵向时间线，桌面右侧 256 px 预算摘要；1199 px 及以下单列，摘要移到日程后方，优先阅读与编辑安排。
- 不使用横向多天看板：手机查看、活动编辑和日期冲突更容易在纵向结构中表达。
- 每天标题包含日期与“添加”次级入口。空的一天保留占位行“添加这天的安排”。
- 有时间的条目按时间排序；无时间条目在当天末尾。上下移动仅改变手动顺序，不覆盖时间排序规则。
- 条目末尾菜单提供编辑、上移、下移、删除，适用范围外的移动说明原因；不以拖拽作为唯一排序方式。
- 私人备注默认折叠，快照预览不包含备注。

### 6.2 预算摘要

- 展示方案原估算、按当前活动修订的估算及差额，清楚区分与实际支出。
- activities 条目计入活动预算，included 条目显示“已含于方案”且不重复累计。
- 有未估算活动时显示“还有 2 项待估算”，已知部分单独列出，不把其总和展示为完整预算。
- 超出成员预算时展开具体成员；确认状态仍以方案为基础，额外提示“日程调整尚未重新征求意向”。
- 页面无须再放实际费用统计，前往账本通过已有导航完成。

### 6.3 D06 活动编辑与异常

- 字段：名称、日期、类别、起止时间、费用归属、每人预计活动支出、备注。
- included 模式隐藏金额输入，显示“费用已含于方案”；activities 模式允许明确输入 0 或留为待估算。
- 首次无日程时允许手工创建草稿，日期选择受草稿绑定范围约束；若尚无范围，先让用户选择搜索窗口内的日程范围。
- 时间重叠为非阻断提醒，起止时间不合法则在字段旁阻止保存。
- 新确认日期与现有日程不一致时，范围外条目集中标识并提供“调整日期”；快照分享被阻止时定位这些条目。
- 替换日程先显示将覆盖的条目数量和确认动作；取消不改变原内容。

## 7. P04 账本

### 7.1 共同结构

标题“账本”，页内分段切换“账目 / 结算”。“账目”主操作为“记一笔”；“结算”在具体建议行记录线下转账，不在标题处放含糊的“全部结清”。

摘要只展示实际总支出和费用笔数，不用默认人均数掩盖不同参与人的承担差异。

### 7.2 账目视图

```text
账本                                               [记一笔]
[账目]  结算
实际支出 ¥390.00 · 2 笔

日期       项目       金额        垫付人       参与情况
……         住宿       ¥300.00     A            3 人均摊
……         餐费       ¥90.00      B            A、B 参与
```

- 费用按日期倒序、创建时间倒序、ID 排列；每行可进入明细。
- 手机转换为金额右对齐的费用列表：名称和金额在首行，日期、垫付人和参与人数在次行。
- 费用详情先展示总额和垫付人，再列每人承担，保留费用模式与尾差结果。
- 没有费用时只展示“还没有费用”和“记一笔”，不展示饼图或虚构分摊。

### 7.3 D07 记一笔

字段顺序：金额 → 项目名称 → 日期/类别 → 垫付人 → 参与成员 → 分摊方式 → 分配预览。

- 参与人列表提供全选和清空，明确勾选者才承担费用；垫付人与参与人独立选择。
- “均摊 / 自定义”切换放在参与人之后。均摊显示最终分配到分的金额；自定义逐人填写并显示待分配差额。
- 底部展示“已分配 ¥100.00 / 总额 ¥100.00”，不足或超出时就地说明。
- 财务明细统一保留两位小数，避免隐藏 0.01 元差额；预估预算可按实际精度简洁展示。
- 有有效结算时，“记一笔”与费用编辑均不能修改数据；操作附近显示“已有结算记录”，提供“查看更正方式”。

### 7.4 结算视图

桌面上方为逐人成员余额表，下方为转账建议和记录；手机按同样顺序堆叠。

成员余额列：成员、已付、应承担、已转出、已转入、当前应收/应付。手机默认显示当前余额，展开看其余明细。

```text
成员余额
A   应收 ¥155.00
B   应付 ¥55.00
C   应付 ¥100.00

转账建议
C → A     ¥100.00                          [记录已转账]
B → A      ¥55.00                          [记录已转账]

结算记录
记录时间 / 转出人 → 转入人 / 金额 / 已记录或已撤销
```

- 应收/应付用文字加颜色，不能只用正负号；财务数字右对齐，采用等宽数字样式。
- D08 展示转出人、转入人、建议金额，允许录入不超双方余额的部分转账金额；确认按钮为“记录此笔转账”。
- 确认前附一次必要说明“仅记录已在线下完成的转账”，无支付图标或支付结果页。
- 记录成功后重新计算建议，已归零者移出建议；保留记录，不让建议行继续可重复点击。
- 全部余额为零时显示“当前已结清”，下方仍可查看真实记录。
- 更正入口位于结算记录区域，打开 D12“撤销全部结算记录”，说明仅撤销本地记录，真实转账不会撤回；撤销后才能改费用，并按真实情况重新登记转账。

## 8. P05 计划快照

### 8.1 布局

独立阅读页，内容最大宽度 880 px，居中，手机单列。顶部是“同路”和“只读快照”，不显示组织者工作台导航。

1. 旅行名称、目的地、日期、时长、生成时的确认状态。
2. 公开估算总览与当前日程差额；若调整未确认，明确说明。
3. 按天公开日程，不展示私人备注。
4. 生成时间和“生成后不会自动更新”短提示。
5. 页面末尾“另存为我的旅行”；入口处也可有低强调跳转，避免固定遮挡日程。

### 8.2 行为与状态

- 只展示 payload 中的内容，不读取本设备同 tripId 的私有成员资料来补全页面。
- 草稿显示“未确认”，不改写成已确认计划；生成时间不是实时报价时间。
- 另存后创建新的本地旅行并进入小队，提示添加成员；不继承原确认、意向、邀请或实际账本。
- 快照文件导入同样进入此只读视图；没有有效方案或数据损坏时进入 P08，不自动创建空旅行覆盖现有内容。

## 9. P06 成员填写

### 9.1 布局与内容

独立轻量表单页，最大宽度 720 px。顶部显示旅行名称、目标成员昵称和“填写后发回组织者”一次提示，不提供虚假的加入成功或在线同步状态。

使用一个页面内的两步流程，顶部仅显示“个人资料 / 方案意向”，不是新增两个站点页面：

1. 个人资料：昵称、出发城市、预算上限、可用日期、偏好；字段规则与成员编辑一致。
2. 方案意向：候选纵向排列，显示日期、个人估算与可判断的时间/预算适配，再给出赞成、可接受、不参加。

- 第一步按钮“查看方案”，第二步按钮“生成反馈”。不称“提交到小队”，因为没有服务器接收。
- 返回上一步保留本次内存草稿；刷新前未导出可能丢失的风险在离开有修改的表单时提示。
- 预算或时间冲突时允许明确表达不参加；即使选择赞成，组织者端仍不能绕过硬约束确认。
- 未知城市导致无法估算时显示“交通待组织者补充”，允许回传资料，不能伪造个人总额。
- 仅展示目标成员可获得的邀请内容，不提供其他成员资料或完整交通映射。

### 9.2 有效性

- 接收端只能校验邀请格式和支持的模板版本，不能知道组织者设备上的邀请是否已过期。
- 不显示“邀请实时有效”；提示反馈是否可应用由组织者导入时校验。
- 模板版本不受支持时保留只读查看，阻止生成新的意向反馈，并提示联系组织者重新生成。
- 不在此页登录或验证身份，成员昵称不代表已通过身份认证。

## 10. P07 反馈回传

### 10.1 页面内容与布局

独立页，最大宽度 720 px，顶部标题“反馈已生成”，随后显示成员昵称、资料摘要和各方案意向。

- 主操作“复制反馈链接”，次级“下载反馈文件”。下面仅保留必要说明“把链接或文件发给组织者，由对方导入”。
- 链接超长时主操作改为“下载反馈文件”；复制失败显示可选中链接，不要求重填。
- 从 P06 进入时提供“返回修改”，保留当前表单草稿；从外部直接打开 response 链接时只展示其内容，不假定存在前一步草稿。
- 不显示“组织者已收到”“已同步”等未经证实的状态。

### 10.2 组织者在本设备打开反馈

- 若本地存在对应旅行，可显示“预览并导入”入口；先打开 D10，不直接改数据。
- 同时保留复制与下载，避免同名旅行或误开的设备被自动覆盖。
- 没有对应旅行时保持回传页，说明需要在保存原旅行的设备导入，不引导新建空旅行来冒充恢复。

## 11. 分享、导入和本地数据弹层

### 11.1 D01 创建与旅行切换

- 创建只要求旅行名，保存后进入空的小队页。
- 旅行切换器区分示例与用户旅行；删除最后一个旅行后提供创建或体验示例入口，不自动恢复已删除数据。
- 重命名保留当前页面，删除旅行需确认具体名称，并提供先导出备份入口。

### 11.2 D03 / D09 邀请与计划分享

- 邀请从目标成员行进入，标题明确“邀请林知夏填写”；展示将分享的范围、复制链接和下载邀请文件。
- 含手工专属交通值时额外列出目标城市和金额，由用户选择是否附带；不把其他成员信息一起导出。
- 计划分享先选择方案，再预览目的地、确认状态、估算和日程；只导出公开白名单，不提供“包含账本”的开关。
- 日程有范围外条目时，面板显示对应日期和“去调整日程”，生成操作说明被阻止的原因。
- 文件超限或链接超长时给出可执行替代；链接超长不截断数据。
- 完整备份是更多菜单里的独立操作，不能与面向成员的计划分享混在一起。

### 11.3 D10 导入预览

统一入口支持粘贴受支持链接、选择 JSON 文件。根据 payload 类型进入相应视图：

| 类型 | 预览内容 | 应用操作 |
| --- | --- | --- |
| feedback/response | 所属旅行、目标成员、旧值→新值、方案意向、有效性 | “应用到此设备” |
| backup | 名称、日期、人数、账目数、本地是否同 ID | 默认另存副本；显式选择覆盖并确认 |
| invitation | 旅行名称、目标成员、支持版本 | “打开填写页”，进入 P06 |
| snapshot | 名称、日期、生成时间 | “查看快照”，进入 P05 |

其中协议类型实际使用 response，界面称“成员反馈”，不向用户暴露英文类型名。

- 同 ID 备份覆盖时展示本地与导入版本的时间及内容差异摘要，旧版导入额外提醒；先保留恢复副本再覆盖。
- 过期反馈只能查看和重新发邀请；重复反馈显示“已应用过”，不会再次写入。
- 校验错误显示具体原因，如“文件中的费用引用了不存在的成员”；不渲染半份数据或只导入有效部分。
- 退出预览不改变本地旅行，真正应用后才出现成功反馈。

### 11.4 D11 本地备份与恢复

- 列出当前旅行与最多 3 份覆盖前恢复副本，显示名称、生成时间和费用数量，支持查看恢复预览、导出与删除恢复副本。
- 导出完整备份前说明含成员资料与账本，文件下载后给予明确结果；不提示已上传云端。
- 配额不足时展示可管理的本地内容及导出入口，不静默删除主旅行。
- 解析损坏的本地数据时保留原始内容，提供下载原始数据、导入备份、确认重置三个路径。

## 12. P08 错误、保存与恢复状态

| 场景 | 页面布局与操作 |
| --- | --- |
| 未知页面 | 简短标题“没有找到这个页面”，按钮“返回旅行”；不丢弃已有本地数据 |
| 未知 tripId | 展示可用旅行选择与导入备份；不把错误 ID 映射为另一个旅行 |
| 分享数据无效 | 保留品牌和错误原因，提供重新导入；返回工作台为次级操作 |
| 首次读取本地数据 | 使用与最终列表结构一致的骨架，不等待期间自动写入新示例 |
| 保存失败 | 保留页面和输入，局部提示“尚未保存”，提供重试、导出当前内容 |
| 存储不可用 | 页面顶端持续提示临时体验模式，提供导出；不显示已保存到设备 |
| 其他标签页已更新 | 阻止旧内容覆盖，提供重新载入、导出当前内容；不自动丢弃编辑草稿 |
| 达对象或存储上限 | 相关操作就近说明，允许编辑、导出和管理已有内容 |

普通空内容不是错误页；例如没有成员仍在 P01，没有账目仍在 P04。可继续阅读的错误不使用全屏遮罩。

## 13. 视觉与基础组件

视觉规格及本文各节的旧布局示意已由 [design.md](./design.md) 的 Design v3 取代（用户选定第 3、6、9、12 张稿）；本节保留历史参考，业务流程与状态清单仍以本文为准。

### 13.1 视觉方向

采用克制的旅行手账视觉：暖白底、青绿导航与主操作、鼠尾草色分区，沿用本地目的地插画。信息通过对齐、分组、分隔线与留白建立层级，避免多层圆角嵌套。

| 项目 | 建议规格 |
| --- | --- |
| 页面底色 | `#F8F9F5` |
| 内容面 | `#FFFFFF` |
| 主要文字 | `#20342F` |
| 次级文字 | `#62716B`，仅用于辅助信息，保持可读对比度 |
| 主色 / 侧栏 | `#18594C` / `#164F44`，用于主要操作、当前导航与焦点 |
| 成功 | `#23634D`，配合“通过/已结清”等文字 |
| 警告与冲突 | `#895414` / `#B33E32`，分别配合待处理/明确错误文字 |
| 边框 | `#DCE3DC`，列表和日程采用平面分隔线，表单与弹层保留必要框线 |
| 字体 | 正文使用 Manrope / 系统中文无衬线回退；品牌、页面与目的地标题使用本机中文宋体回退，形成手账气质；不下载远程字体 |
| 字重 | 正文 400，交互 600，标题不超过 700；无斜体 |

字体资源不可成为访问依赖。未提供本地 Manrope 字体时使用系统回退即可，所有核心内容仍需完整呈现。

### 13.2 尺寸与间距

- 页面标题：桌面 36/48 px，手机 30/40 px；分区标题 20/28 px；列表正文 14/24 px；日期、来源等辅助信息 12/20 px；手机输入控件 16/24 px，避免移动浏览器聚焦缩放。
- 间距使用 4、8、12、16、24、32、40、48、64 px；页面主要区域间距 24，卡片内边距 16 或 24。
- 弹层圆角 8 px，输入与按钮 6 px，导航与轻量控件 4 px；横幅和抽屉直角，列表与日程不添加外层圆角卡片。
- 表单控件与点击区域高度至少 44 px；按钮内边距为上下 8、左右 16 px，结合最小高度约束。
- 图标统一使用 Lucide（lucide-react），具名静态导入，不整包加载。默认 20 px、线宽 2，辅助图标可用 16 px、导航可用 24 px；保持线性风格，选中状态通过底色和文字颜色表达。主要操作保留文字，不能仅凭图标猜含义。
- 背景使用纯色，不使用大面积渐变、模糊玻璃背景或重阴影来区分数据。

### 13.3 交互状态与可访问性

- 按钮、链接、列表行具备 hover、active、focus、提交中、禁用/不可执行状态；禁用原因可见。
- 按钮采用 160 ms 的颜色、边框、阴影与轻微位移反馈，采用 `cubic-bezier(0.22,1,0.36,1)`；保存中有旋转图标与真实状态文字，不增加阻塞操作的入场动画。
- 弹层由固定标题、可滚动正文和固定操作栏组成；打开时锁定背景滚动。菜单支持点击外部关闭、Escape 退出并恢复焦点。
- 减少动态效果偏好下取消位移；首屏数据不使用滚动入场动画隐藏。
- 弹层打开后焦点进入内部，关闭回到原触发点；Escape 可退出，有未保存修改时先确认。
- 同一时刻只保留一个大表单或详情层；危险确认可以短对话框出现，关闭后回原编辑状态。
- 浏览器返回应先关闭当前大抽屉或退回前一步，底层路由不跳错；可通过 Hash 中的视图参数实现，不新增顶部导航项。刷新打开的详情时可恢复只读位置，不承诺恢复未提交表单。
- 公开页面和工作台都提供明确返回路径、跳转主内容入口、语义化标题与表单标签。
- 正文对比度至少 4.5:1；颜色不单独承担冲突/完成含义；图像有恰当替代文本，装饰图用空替代文本。
- 确认状态、本地保存、只读和演示标记使用产品语言，不展示 revision、schemaVersion 等实现字段。
